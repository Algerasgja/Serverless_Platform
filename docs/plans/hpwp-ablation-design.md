# HPWP 消融实验设计（论文式说明，三阶段版）

## 1. 研究目标
本消融实验的目标是验证 HPWP 中“上下文感知”与“运行期自适应”两类机制是否能在同一执行环境下产生可解释的分层收益。实验不做跨算法横向比较，而是在同一算法家族内部逐步开启机制，观察 `Avg/P95/P99` 的变化轨迹，从而回答“哪些组件真正贡献了性能提升，提升幅度是否稳定”的核心问题。

## 2. 组件拆分与职责说明

### 2.1 组件A：上下文层次预测（Hierarchy + Prefix Context）
该组件通过后缀上下文层次对下一跳转移概率进行建模，核心作用是让路径预测不再只依赖“当前节点”，而是显式利用“当前节点之前的一段已执行前缀”。当请求进入分支节点时，系统会使用更长上下文进行更细粒度判断；当长上下文样本不足时会自动回退到短上下文，从而在“准确性”与“鲁棒性”之间取得平衡。

### 2.2 组件B：紧迫时间门控（Urgency Gate）
该组件负责把“预测到会执行的函数”进一步筛成“需要马上预热的函数”。具体做法是利用预测到达时间与冷启动可达条件进行约束，只在窗口内且存在冷启动风险的目标函数上分配预热预算。它的主要价值是抑制无效扩容，避免把容器资源浪费在短期内不会触达的函数上，保证扩容动作与真实时序更一致。

### 2.3 组件C：相位自适应（Phase Adaptation）
该组件根据近期 Hit@1 统计波动，在线切换探索态与稳定态，并同步调整学习强度与有效上下文深度。探索态用于快速吸收新模式，稳定态用于降低噪声与抖动。其作用不是直接“多扩容”，而是通过改变预测更新行为，提高模型在不同负载阶段下的稳定性，降低因短时波动造成的错误预测与无效预热。

### 2.4 组件D：漂移处理（Drift Handling）
该组件在检测到短窗误差显著抬升时触发，执行局部遗忘与参数回退，避免旧模式持续主导当前决策。它的目标是提升模型在非平稳流量中的恢复速度，尤其是在上下文模式发生变化后尽快回到可用状态。该机制重点解决“模型过时”问题，而不是简单提高平均扩容强度。

### 2.5 组件E：基线约束与对照骨架（Core Baseline Envelope）
该组件用于定义消融基线的行为边界，包括低上下文深度、严格门控、保守周期等。其意义是构造一个稳定、可复现、能力受限的起点，以便清晰测量后续组件带来的增量收益。没有该组件，消融会退化为参数混合对比，无法明确归因“到底是哪一类机制带来了提升”。

## 3. 三阶段消融编排（当前实际实现）
脚本：`analysis/ablation_experiments.py --scheme progressive`

| 阶段 | 组块名 | 启用机制 | 说明 |
|---|---|---|---|
| G0 | `g0_base` | 仅基线骨架 | 关闭上下文增强、关闭相位与漂移，保守策略作为起点 |
| G1 | `g1_context` | 基线 + 上下文预测 | 仅恢复层次上下文预测，验证“上下文感知”本身的收益 |
| G2 | `g2_context_phase_drift` | G1 + 相位自适应 + 漂移处理 | 在上下文基础上加入运行期自适应能力，验证进一步增益 |

说明：当前论文主线采用三阶段设计，不再使用旧版五阶段（G0-G4）累进链路。

## 4. 控制变量与公平性设置

### 4.1 冻结关键超参数
以下 5 个关键参数在全部阶段中强制一致，并从 `results/hparam_best.yaml` 读取：
- `hpwp_sched_eta_exec`
- `hpwp_horizon_alpha`
- `hpwp_beta_hi`
- `hpwp_beta_lo`
- `hpwp_alpha_stable`

若任一阶段覆盖上述字段，脚本会直接报错中止，以防“组件效果”被“关键参数漂移”污染。

### 4.2 负载场景
三档相对负载保持不变：
- `low = 0.5x`
- `mid = 1.0x`
- `high = 2.0x`

### 4.3 运行轮次（加快迭代）
当前默认 seeds 为 `42, 43`，用于快速迭代验证：
- 默认总运行量：`3 场景 × 3 阶段 × 2 seeds = 18 runs`

如需更稳统计，可手动扩展 seeds（例如 5 seeds）。

## 5. 指标与统计口径
本消融主分析聚焦：
- `avg_e2e_ms`
- `p95_ms`
- `p99_ms`

并自动输出以下增益字段：
- `delta_avg_vs_prev_pct`
- `delta_p95_vs_prev_pct`
- `delta_p99_vs_prev_pct`
- `delta_avg_vs_g0_pct`
- `delta_p95_vs_g0_pct`
- `delta_p99_vs_g0_pct`

## 6. 输出文件与图表
- `results/ablation_metrics.csv`：按“场景+阶段”聚合统计
- `results/ablation_pairwise.csv`：按同 seed 配对差分
- `results/ablation_e2e.png`：三场景子图，展示 G0→G2 的 `Avg/P95/P99` 曲线与阶段差分标注

注：当前版本不再输出 `ablation_gain.png`。

## 7. 结果判读规则（建议）
1. 先看 `G1 vs G0`：确认“上下文预测”是否产生稳定收益。  
2. 再看 `G2 vs G1`：判断“自适应机制”是否带来增量且不破坏稳定性。  
3. 最后看三场景一致性：低中高负载下趋势是否同向，避免单场景偶然性结论。

## 8. 复现实验命令
```powershell
python analysis/ablation_experiments.py --config configs/default.yaml
```

快速单轮试探：
```powershell
python analysis/ablation_experiments.py --config configs/default.yaml --seeds 42
```

扩展统计轮次：
```powershell
python analysis/ablation_experiments.py --config configs/default.yaml --seeds 42 43 44 45 46
```
