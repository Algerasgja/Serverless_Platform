# Oracle（`oracle_future_v1`）调参经验

## 核心思想
Oracle 是理想上界：已知真实未来路径，仅对窗口内“确定会被使用”的函数补齐容器，目标是尽量消除冷启动。它的意义不是工程可部署，而是给出可达到的性能边界。

## 参数说明与使用建议
- `oracle_window_steps`：
  经验：窗口步数越大，越接近“全路径提前预热”，成本也越高。通常用于研究“信息完备时收益上限”。
- 周期参数沿用全局：
  经验：若周期太慢，即便是 Oracle 也会出现时机错过，导致上界不够“理想”。

## 解释口径建议
1. 在主延迟图里可将 Oracle 作为参考边界；
2. 在成本图中必须单独解释其“理想信息优势”；
3. 不建议把 Oracle 与可部署策略做绝对公平比较，更适合用作 gap 分析基准。
